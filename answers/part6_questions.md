# Часть 6: Контрольные вопросы

## 1) В каком порядке выполняются конструкторы при создании объекта подкласса?
_Ваш ответ: Сначала вызывается конструктор родительского класса (явно через super(...) или неявно — конструктор по умолчанию без параметров), затем выполняются инициализаторы полей и конструктор самого подкласса.
Пример:

java
class Parent { Parent() { System.out.println("Parent"); } }
class Child extends Parent { Child() { System.out.println("Child"); } }
new Child(); // выведет Parent, затем Child
Типичная ошибка: забыть вызвать super(...) в конструкторе подкласса, если у родителя нет конструктора по умолчанию — компилятор выдаст ошибку.
_

## 2) Можно ли переопределить `static` метод? Что такое method hiding?
_Ваш ответ: static методы не переопределяются, они скрываются (hiding). Если в подклассе объявить такой же статический метод (с той же сигнатурой), то он не заменяет метод родителя, а скрывает его — выбор метода зависит от типа ссылки на этапе компиляции, а не от типа объекта во время выполнения.
Пример:

java
class Parent { static void foo() { System.out.println("Parent"); } }
class Child extends Parent { static void foo() { System.out.println("Child"); } }
Parent p = new Child(); p.foo(); // Parent, хотя объект Child
Child c = new Child(); c.foo(); // Child
Ошибка новичка: думать, что статические методы ведут себя как обычные (виртуальные) и надеяться на полиморфное поведение._

## 3) Что произойдет, если в `switch` нет `default` и ни один `case` не совпал?
_Ваш ответ: Ничего не произойдёт — управление просто передастся за пределы блока switch, никакой ошибки не будет.
Пример:

java
int x = 5;
switch (x) {
case 1: System.out.println("1"); break;
case 2: System.out.println("2"); break;
}
   код выполнится без вывода и без исключения
Ошибка: новички иногда ожидают, что без default вылетит исключение, но это не так._

## 4) Почему в `for-each` нельзя удалять элементы коллекции? Как правильно?
_Ваш ответ: for-each (enhanced for loop) использует неявный итератор. При удалении элемента напрямую через коллекцию (например, list.remove(e)) итератор становится «испорченным» — при следующей итерации выбрасывается ConcurrentModificationException.
Правильный способ: использовать явный итератор и его метод remove(), либо собирать удаляемые элементы в отдельный список и удалять после цикла, либо использовать removeIf() (Java 8+).
Пример:

java
List<String> list = new ArrayList<>(List.of("A","B","C"));
Iterator<String> it = list.iterator();
while (it.hasNext()) {
if (it.next().equals("B")) it.remove(); // OK
}
// или list.removeIf(s -> s.equals("B"));
Ошибка: попытка удалить элемент внутри for-each: for (String s : list) list.remove(s);_

## 5) Чем отличается `break` с меткой от обычного `break`?
_Ваш ответ: Обычный break прерывает выполнение ближайшего цикла (for, while, do-while) или оператора switch.
break с меткой прерывает выполнение внешнего цикла или блока, на который указывает метка. Позволяет выйти из нескольких вложенных циклов сразу.
Пример:

java
outer: for (int i = 0; i < 3; i++) {
for (int j = 0; j < 3; j++) {
if (i == 1 && j == 1) break outer; // выход из обоих циклов
}
}
Ошибка: путать метки с goto (но break с меткой — это не goto, он не прыгает в произвольное место, только за пределы помеченного блока)._

## 6) Что означает `@Override`?
_Ваш ответ: @Override — это аннотация, указывающая компилятору, что метод переопределяет метод родительского класса или реализует метод интерфейса. Компилятор проверит, существует ли такой метод в суперклассе/интерфейсе, и выдаст ошибку при несовпадении сигнатуры. Это защита от опечаток и случайной перегрузки.
Пример:

java
class Parent { void foo() {} }
class Child extends Parent { @Override void foo() {} } // правильно
// @Override void f00() {} // ошибка, метод не переопределяет ничего
Ошибка новичка: использовать @Override при перегрузке (другая сигнатура) — компилятор сообщит об ошибке.

_

## 7) Какой модификатор доступа выбрать для видимости в подклассах?
_Ваш ответ: Для видимости в подклассах (даже если они находятся в другом пакете) нужно использовать модификатор protected. Он даёт доступ в том же пакете + из подклассов вне пакета.
Если подкласс находится в том же пакете, достаточно package-private (без модификатора).
Пример:

java
public class Parent { protected int x; }
public class Child extends Parent { void bar() { x = 10; } } // доступно
Ошибка: думать, что private виден в подклассе, или что public — единственный способ для подклассов._

## 8) Разница между `final` классом и `sealed` классом?
_Ваш ответ: final class — класс, который нельзя наследовать вообще. Никакой подкласс создать невозможно.
sealed class (Java 17+) — разрешает наследование только для ограниченного набора указанных подклассов. Запрещает произвольное наследование, давая контролируемую иерархию.
Пример:

java
final class A {}         // нельзя extends A
sealed class B permits C, D {} // B могут наследовать только C и D
final class C extends B {}
non-sealed class D extends B {} // D могут наследовать другие
Ошибка: думать, что sealed — это то же самое, что final. sealed допускает наследование, но только от явно разрешённых классов._

## 9) Можно ли иметь несколько конструкторов?
_Ваш ответ: Да, в классе может быть несколько конструкторов — это называется перегрузкой конструкторов. Они отличаются количеством или типами параметров. Один конструктор может вызывать другой через this(...).
Пример:

java
class Point {
int x, y;
Point() { this(0, 0); }
Point(int x) { this(x, 0); }
Point(int x, int y) { this.x = x; this.y = y; }
}
Ошибка: рекурсивный вызов конструкторов (цикл через this), а также попытка вызвать конструктор суперкласса и this(...) одновременно — запрещено._

## 10) Что такое ковариантный тип возвращаемого значения?
_Ваш ответ: Ковариантность возвращаемого типа означает, что переопределяющий метод может возвращать более конкретный (подтип) типа, указанного в родительском методе. Это разрешено начиная с Java 5.
Пример:

java
class Parent { Number get() { return 0; } }
class Child extends Parent { @Override Integer get() { return 0; } } // Integer — подтип Number
Ошибка: попытка вернуть более общий тип (надтип) — недопустима, это инвариантность или контравариантность, не поддерживаемая при переопределении._
